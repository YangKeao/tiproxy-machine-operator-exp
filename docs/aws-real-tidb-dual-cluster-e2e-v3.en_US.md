# TiProxy Machine Operator: Real TiDB Dual-Cluster Cross-VPC Peering Validation Plan V3

This document records the V3 rerun: first destroy the three dedicated V2 test VPCs and their exclusive dependencies, then recreate three fresh environments from empty AWS resources and complete end-to-end validation again.

## Goal

- Destroy the three V2 test VPCs from the previous round and their exclusive dependency resources.
- Create one new `TiProxy VPC + EKS`.
- Create two new `TiDB VPC + EKS` environments and deploy one minimal TiDB cluster in each.
- Create two VPC peerings.
- Expose CoreDNS inside the two TiDB VPCs through internal NLBs using the legacy service-controller semantics.
- Run the real manager inside the TiProxy EKS.
- Create:
  - `TiProxyMachineGroup`
  - two `TiProxyMachinePort`
  - two `TiDBResourcePoolLink`
- Validate TiProxy dual-port routing with real TiDB data.

## Problems Found in This Round

- Names generated by the current AWS provider for NLBs, target groups, ASGs, and launch templates can still collide with historical test resources at the global AWS name level.
  - In the first attempt of this round, directly using `demo` caused the target group `tpm-default-demo-p6002` to fail because of a name conflict.
  - The actual workaround was to use the unique machine-group name `demo-v3`.
- In the current operator/agent path, `TiDBResourcePoolLink.spec.pdAddresses` still cannot be omitted completely.
  - When only `nsServerAddress` was set, the agent reported: `cluster "tc-a" has empty pd addresses`
  - The actual workaround used in this round was to fill the Link explicitly with:
    - `tc-a-pd-peer.tidb.svc.cluster.local:2379`
    - `tc-b-pd-peer.tidb.svc.cluster.local:2379`
- In the middle of this round, both TiDB clusters needed a manual `associate-iam-oidc-provider`, which caused the latter half of the original `eksctl create cluster` convergence to fail.
  - The control plane remained successfully created.
  - The actual workaround was to create the nodegroups manually afterward using `eksctl create nodegroup`.
